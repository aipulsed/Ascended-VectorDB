# Data Model

Ascended-VectorDB uses **PostgreSQL 16** with the **pgvector** extension. All primary keys are UUIDs generated by the `uuid-ossp` extension. The schema is managed via Prisma Migrate.

---

## ERD Overview

```
Tenant (root, no FK back-references)
│
├── Workflow ─────────────────┐
│                             │
├── Execution ◄───────────────┘  (workflow_id nullable)
│   └── Task
│   └── Event
│
├── Document
│   └── DocumentChunk
│       └── Embedding ◄─────── also ← AgentMemory
│
├── AgentMemory
│
└── ApiKey
```

## Enums

### `WorkflowStatus`

| Value | Description |
|---|---|
| `DRAFT` | Workflow is being authored; not yet active |
| `ACTIVE` | Workflow is live and can be executed |
| `ARCHIVED` | Workflow is retired; read-only |

### `ExecutionStatus`

| Value | Description |
|---|---|
| `PENDING` | Created, not yet started |
| `RUNNING` | Currently executing |
| `COMPLETED` | Finished successfully |
| `FAILED` | Terminated with an error |
| `CANCELLED` | Manually cancelled |
| `PAUSED` | Temporarily paused, awaiting resumption |

### `TaskStatus`

| Value | Description |
|---|---|
| `PENDING` | Task queued, not started |
| `RUNNING` | Task is actively executing |
| `COMPLETED` | Task finished successfully |
| `FAILED` | Task encountered an error |
| `SKIPPED` | Task was intentionally bypassed |
| `RETRYING` | Task is retrying after a failure |

### `DocumentStatus`

| Value | Description |
|---|---|
| `PENDING` | Ingested but not yet processed |
| `PROCESSING` | Chunk extraction in progress |
| `READY` | Fully processed and indexed |
| `FAILED` | Processing encountered an unrecoverable error |

### `MemoryType`

| Value | Description |
|---|---|
| `SHORT_TERM` | Fast key-based lookup; typically ephemeral or short-lived |
| `LONG_TERM` | Persisted; eligible for vector similarity recall |

## Index Strategy

- **Composite indexes on `(tenant_id, status)`** — Execution and Task tables: efficient filtering of in-progress jobs per tenant.
- **`(tenant_id, created_at)`** on Execution — time-range queries for audit/analytics.
- **`(tenant_id, type)` and `(tenant_id, timestamp)`** on Event — event type filtering and chronological timeline queries.
- **`(document_id)`** on DocumentChunk — chunk lookup by parent document.
- **`(tenant_id, agent_id)`** on AgentMemory — all-memories-per-agent queries.
- **Unique `(tenant_id, agent_id, key)`** on AgentMemory — upsert semantics.
- **HNSW vector index** on `Embedding.embedding` — approximate nearest-neighbor search with `m=16, ef_construction=64`.

## UUID Primary Key Rationale

All primary keys are UUIDs (v4) rather than auto-increment integers because:

1. **Distributed generation** — IDs can be generated in application code without a DB round-trip.
2. **No sequential enumeration** — prevents trivial object enumeration attacks.
3. **Multi-tenant safety** — IDs are globally unique across tenants.
4. **Ecosystem interoperability** — the Ascended-SDK and connected services can pre-compute IDs before insertion.

## Soft Delete Pattern

`Document.deleted_at` follows the soft-delete pattern:

- On `DELETE /documents/:id`, the service sets `deleted_at = NOW()` rather than issuing a SQL `DELETE`.
- All application-level queries filter `WHERE deleted_at IS NULL`.
- Data is retained for audit purposes and can be restored by clearing `deleted_at`.
- Associated `DocumentChunk` and `Embedding` records are **not** automatically deleted; use the reindex endpoint to clean up embeddings.
